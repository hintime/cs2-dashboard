## P0：BUFF 求购侧数据缺失（最严重）

### 证据
- `csqaq_boards.json`（4785 条，09-17 回填）字段仅有：
  `buff_sell / buff_sell_num / yyyp_sell / yyyp_sell_num / steam_sell / steam_sell_num`
  → **没有 `buff_buy` / `buff_buy_num`**（求购侧）。实测非 0 计数：**0**。
- 推荐池 30 条中 `buff_buy = buff_buy_num = 0`，**30/30**；全池仅 18 件有该字段。

### 根因链（层层递进）
```
BUFF 求购数据缺失（buff_buy / buff_buy_num 恒为 0）
  → 评分 B1「买卖盘强度」(35 分)：`if bsn>0 and bbn>0: buff_max += 35` → 条件不成立，整项跳过
  → 评分 B3「买盘贴价」  (25 分)：`if bb>0 and bs>0:  buff_max += 25` → 整项跳过
  → buff 维度实际只由 B2(在售深度 20) + B4(Steam偏离 20) 构成
     （注：分母 buff_max 也同步不含 B1/B3，**不存在"分母虚高"**；损失的是维度语义，不是算术）
  → buff_reasons 为空（其来源 B1/B3 被跳过；B4 需 |dev|>25，实测最大 16.5，不触发）
  → update.py:1078 `if buff_score > eco_score and buff_reasons` 恒为 False
  → tag 恒为 'eco'（前端契约 tag∈{eco,buff} 中的 buff 事实上消失）
```
实测印证：当前 30 条推荐 `tag` **全部为 eco**，而 `buff_score` 均值 85.8 远高于 `eco_score` 62.9
（即"本该是 buff 主导"的标的，因缺理由而被归到 eco）。

### 影响
1. BUFF 维度（权重 0.35，经教训调整后 0.42，已是最大权重）**语义被削去一半**：
   最能反映真实盘口松紧的「买卖盘强度 / 买盘贴价」两项完全缺失，只剩「在售深度 + Steam 偏离」；
2. 前端与理由在讲"买盘坚挺/求购活跃"，而这些其实来自 **ECO 侧 A1/A2**，并非 BUFF 盘口 →
   叙事与数据来源不一致（用户容易误以为 BUFF 买盘已验证）；
3. 前端按 tag 的筛选/统计失真（buff 分组恒为空）。

### 修复方向（需数据源，非纯代码）
- 查 CSQAQ 批量接口是否提供**买单/求购**字段；若无 → 需补数据源（部分平台 buy 侧接口）；
- 在拿到数据前，应在 UI 明确标注该维度仅含「在售深度 + Steam 偏离」；
- `tag` 判定不应依赖"有无理由"，建议直接用维度得分比较（或补足理由来源）。

## P1：缺数据维度「不参与」造成逆选择

### 机制
评分对缺失维度采取"不参与、不拉低均值"。方向正确（不惩罚无数据），但**结构不对称**：
- 无 Steam 数据：`buff_max = 20`（仅 B2）→ B2 拿满即 `buff_score = 100`；
- 有 Steam 数据：`buff_max = 40`（B2+B4）→ 通常 `buff_score ≈ 80`。

### 实测
| n_cov | 条数 | 平均分 | 是否有 Steam 数据 |
|---|---|---|---|
| 0.56 | 16 | **77.6** | 否 |
| 0.78 | 14 | **71.0** | 是（14/14） |

→ **有 Steam 数据的标的系统性低 6.6 分**；`corr(score, n_cov) = −0.78`。

### 影响
数据更全（多源交叉验证）的标的被**系统性扣分**，与"鼓励多源验证"的目标相反；
长期会把推荐池推向**单源、难以交叉验证**的标的。

### 修复方向
- 缺失维度按**该维度的池内均值**补全（而非"不参与"），使有无数据可比；
- 或对 `buff_score` 采用**固定分母**（B1/B2/B3/B4 各固定满分），缺失项记 0 但在 UI 明示"数据缺失"。

## P1：维度权重来自未经验证的 AI 教训

- `update.py:1061-1063` 用 `eco_mult / buff_mult`（来自 `tracking_lessons.json`）作为**维度权重**（0.50×eco / 0.35×buff / 0.15×悠悠）。
- 当前值 `ECO×0.80 / BUFF×1.20` 由 AI 根据叙述生成，**没有任何实测收益支撑**（本次记分卡证明"稀缺"类信号实测为负贡献）。
- 同时 BUFF 维度独占 0.42 权重 → 而该维度 60% 分项已失效（见 P0）→ **总分实际由两个未经验证的维度驱动**。

### 修复方向
- 在 dims 数据攒够后，用 `rec_outcomes.csv` 的实测收益做**回归/分档标定**，替换 AI 猜测；
- 在此之前，权重应回到中性（eco≈buff≈悠悠按设计比），避免"猜出来的权重"影响排序。

## P2：命名与口径

| 现象 | 实测 | 说明 |
|---|---|---|
| `n_supply` | 与 `eco_selling` **完全相同**（min/max/mean/stdev 一致） | 名为"供给稀缺"实为**在售件数**（update.py:1168） |
| `n_ref` vs `n_steam` | 两字段**恒等**（同一值） | 冗余，建议合并 |
| `n_cov` | 仅 2 个取值（0.56 / 0.78） | 区分度极低，作为"覆盖度"维度信息量有限 |
| 「稀缺」 | A3 满分仅 20/100；`corr(score, n_supply)=+0.14` | 理由与 `tag_label` 大量强调"稀缺"，与评分权重不符 |
| `tag_label` | 30 条仅 26 个去重值，主力模板「求购活跃·在售X件 · 优选」 | 模板化 |
| 独立基准 | `n_ref=0` / `n_steam=0` 的有 **16/30** | 溢价维度缺失仍推荐（UI 显示"无独立市场基准"） |

---

## 建议的修复顺序
1. **P0**：查清 BUFF 求购数据能否获取（数据源问题）；拿不到就在 UI 标注该维度语义已缩减，
   并把 `tag` 判定改为按维度得分（而非"有无理由"）——恢复 buff 分组；
2. **P1**：缺失维度改为"按池内均值补全"，消除数据越全分越低的逆选择；
3. **P1**：权重回到中性，等 `dims` 攒够样本后按实测标定；
4. **P2**：统一命名（`n_supply`→在售件数语义、合并 `n_ref/n_steam`）、`tag_label` 去模板化。
